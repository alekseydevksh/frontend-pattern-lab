# Editorial rules

How lesson text is written. These come on top of the content rules in [SPEC.md](SPEC.md) (section 7) and
[CLAUDE.md](../CLAUDE.md). They apply to every lesson, from lesson 7 on, and to the editorial pass over
lessons 1 to 6 in M6 (see [PROGRESS.md](PROGRESS.md)).

## Rules

1. **Every lesson says when NOT to use the pattern**, in its verdict table or in its last step. No
   universal rules: every pattern has a price, and the lesson names it.
2. **Modern notes are allowed only when verified.** A note on what newer React features change, or any
   other claim about a current API or behaviour, goes in only when it has been checked against official
   documentation or another primary source. If a claim cannot be verified, leave it out.
3. **Keep the fact log below.** Each verified claim gets a row: the claim, the source URL and the date it
   was checked. A lesson that makes a claim about an API or a behaviour has a row for it.
4. **No third-party library names in lessons.** React's own APIs may be named when verified (rule 2).
5. **All text is original.** The source article is only an inspiration for the topic list. Never copy or
   closely paraphrase it.
